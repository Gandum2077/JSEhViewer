# 数据库同步

在“更多 → 数据库同步”设置和管理 Cloudflare Worker 同步。

## 首次设置

1. 部署 [cloudflare-d1-sync](https://github.com/Gandum2077/cloudflare-d1-sync)，完成数据库迁移，并保存部署时设置的主密钥。本版本要求 Worker API 1、数据库结构版本 3。
2. 点击“连接同步服务”，输入 Worker 的 HTTPS 网址、64 位小写十六进制主密钥，以及便于识别的设备名称。网址可以带 `/v1`，不要附带密钥或查询参数。
3. 连接验证成功后点击“开始首次同步”。应用先备份本机数据库，再下载、合并和上传。首次同步期间保持 JSBox 在前台；中断后再次点击同步即可恢复。
4. 确认结果后按需开启“自动同步”。其他设备用同一网址和密钥连接，各自填写设备名称。

请在各设备上独立初始化应用，不要将带有设备标识的 database.db 复制到另一台设备继续使用。

## 哪些内容参与同步

同步图库资料、阅读进度、收藏与评分状态、图片收藏记录、搜索历史及书签、本地标签和上传者标记、阅读器参数、AI 翻译与 WebDAV 服务定义。标签访问次数按设备独立累计，界面显示所有设备分量的总和。

图片文件、下载任务、网站标签缓存、Cookie、WebDAV 用户名和密码、AI 标记为 secure 的配置均不上传。其他设备同步到 WebDAV 定义后，需要在本机 WebDAV 设置中填写认证信息，或确认使用匿名访问，再启用服务。AI 敏感字段也需要逐台补充。

Worker 网址和主密钥保存在 `assets/credentials.json` 的 `sync` 对象中。此文件与数据库分开管理，不会打入安装包。请勿公开凭据文件。

删除记录也会同步到其他设备，包括主动清理阅读历史或图片收藏产生的删除；普通图片缓存清理不改变云端记录。

## 日常管理

- **立即同步**：接收云端修改并上传本机修改，查看上次成功时间、待处理数量和错误。
- **自动同步**：前台运行时定期检查。断网保留修改并逐步延长重试间隔，关闭 JSBox 后下次打开继续。
- **暂停当前同步**：关闭自动同步，当前网络请求结束后暂停。已在云端提交的内容仍保留。
- **冲突**：同一字段出现不同修改时，对照本机与云端内容，选择保留本机或采用云端。保留本机后再次同步提交。图库与附属记录有依赖时，按提示先处理相关记录。
- **管理设备**：查看设备、重命名或解绑。解绑不会删除历史访问次数，也不能撤销设备持有的主密钥；丢失设备时应在 Cloudflare 更换主密钥，并更新其他设备的连接设置。
- **断开服务**：移除本机保存的连接信息，保留本机和云端业务数据。切换服务会重新合并，原服务的待重试批次取消。

首次同步备份位于 `assets/database.db.before-sync-<UUID>.db`。需要恢复时先关闭自动同步并退出应用，保留当前数据库和 credentials.json 的副本，再替换数据库。恢复旧库后重新连接会再次合并云端现有内容；它不会自动回滚云端数据库。
