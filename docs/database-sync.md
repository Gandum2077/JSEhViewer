# 数据库同步

入口：**更多 → 数据库同步**。使用重新实现的 cloudflare-d1-sync JSON 协议（`/v1/write`、`/v1/sync`、`/v1/full-download`），不兼容旧版业务表后端。

## 使用

1. 配置 Worker 的 HTTPS 根地址及 64 位小写十六进制主密钥；保存后注册设备并验证连接。
2. 选择同步内容。依赖图库的表必须同时选择图库记录。标签列表、搜索词随主记录打包，不单独选择。
3. 点击立即同步。本版本由用户手动触发，不设置后台定时上传。
4. 如有冲突，进入冲突管理选择保留云端，或明确选择使用本机内容，再执行同步。

首次选择某张表时，本机已有数据保留为待上传意图。云端相同内容自动消除重复；不同内容保留为冲突。关闭表不会删除本地或云端记录，再次启用会完整下载及补拉。服务端仍返回全局分页，表选择在客户端过滤，不减少服务端全局分页读取量。

API 地址和主密钥保存在 `assets/credentials.json` 的 `sync: {url, masterKey}`，沿用文件原子替换及 SQLite revision 恢复机制。安装包排除凭据文件和运行时数据库。Cookie、GitHub Token、WebDAV 凭据、AI 敏感参数、下载任务不上传。AI `selected` 和 WebDAV `enabled` 不进入 content；下载新增服务默认关闭，已有服务保留本机选择，删除服务会关闭本机选择。

v1-to-v2 迁移将 `config.githubToken` 保存到凭据文件的 `githubToken`，将 AI 表单中 `secure: true` 字段的值按服务 ID 保存到 `aiTranslation: { [id]: { [key]: value } }`，并清空数据库中的敏感默认值。后续修改 secure 标记时，值在数据库和凭据文件间转移；删除字段或服务会清理对应凭据。所有凭据修改使用同一套文件原子替换与 SQLite revision 恢复机制，不使用 `$keychain`。

同步日志显示无法应用的记录及失败类别，不保存主密钥、请求正文或底层数据库错误。设备管理支持禁用/重新启用。同步身份重建仅用于无未确认请求时的旧备份恢复；数据库及设备身份不能直接复制给另一个安装实例使用。

## 持久化状态

- `sync_enabled`：所选逻辑表。
- `sync_mirror`：已确认的云端 JSON、版本及 tombstone，无业务外键。
- `sync_pending`：本地待上传键、首次编辑的 base version、修订号及冲突选择。
- `sync_meta`：设备请求身份、已提交 seq、最近请求编号、原始未确认请求正文及对应修订号、完整下载标记。
- `sync_stage`：本轮分页下载的暂存记录。
- `sync_log`：按表/ID 保存最近一次无法应用的原因。
- `sync_control`：本地修订号及远端应用期间的写入跟踪开关。

初始化在业务库迁移完成之后、业务操作之前进行。触发器在业务写入同一事务内记录待上传意图，附属表变化也标记主记录；远端应用不会反向产生本地上传。其他设备的标签计数不会进入本机上传队列。

同一个运行实例的同步任务串行。上传前将最多十个不同键的有序请求序列化一次并落盘，传输 NSData UTF-8 字节；未确认结果前不能发送下一编号或切换服务器。已提交但响应丢失的请求原样重放。成功后按保存的修订号清理待上传项；发送期间的新修改继续保留，并更新其 base version。失败项保留冲突，不自动 forced。

分页先暂存，按 sync_version 拒绝版本倒退。所有增量暂存请求使用 `include_self:true`，避免提前确认尚未提交的分页进度；业务应用与 seq 提交完成后才发送普通同步确认。完整下载从 start_seq 补拉至末页，随后切换镜像。中断后保留正式游标，下次清空暂存区重读；日志过期最多自动重启三次完整下载。

业务应用先图库记录，后外键关联表；正常页使用批量 SQL（每条 SQL 最多 900 个绑定参数），坏页回滚后再逐条用 SAVEPOINT 隔离。外键或内容约束失败只跳过本次业务写入，保留云端镜像和错误，后续同步再次尝试。磁盘、事务等基础设施错误回滚整轮应用和游标。通常尚未下载过的 tombstone 无需构造空的业务行；本地标签标记例外：由 namespace:name 恢复删除行，以继续隐藏网站下载的标签。云端从未存在过的标签删除意图会通过两个独立、可重试的 create/delete 请求建立 tombstone，期间保留本地删除意图；全局设置删除恢复本机默认值，删除版本保存在镜像中。

## 大数据量处理

上传队列使用 `(tablename, revision, id)` 条件索引，每次读取最多十条；上传确认只更新对应业务行的版本，不重放镜像或重载业务缓存。批次之间交还事件循环，过滤大量相同内容时也会让出执行时间。

下载只应用本轮暂存键和待重试错误记录，并跳过业务表中已有的相同版本。成功提交后只刷新受影响的缓存；搜索历史和书签的附属搜索词各用一次 JOIN 查询加载，避免逐条读取。完整下载仍保留整轮应用与游标一起提交的原子性。

同步页的进度文字最多每 500ms 更新一次，不在每批上传后重新读取凭据、统计整张队列或重建列表；完成后再刷新数量。

规模回归使用 15000 条搜索历史和 45000 条附属搜索词，覆盖完整上传、完整下载和重复空同步，并检查读取记录数量及写入调用数量随数据量线性增长。测试的本机耗时不代表移动设备或真实网络耗时。

## 验证

```sh
npm run check:database
tsc --noEmit
npm run build
```

可选实际 Worker 互通测试（Node.js 22+，相邻后端项目已安装依赖）：

```sh
D1_SYNC_REPO=/absolute/path/to/cloudflare-d1-sync node --test --test-name-pattern=interoperates scripts/check-database.cjs
```

该测试直接编译后端源码，运行临时 workerd/D1，用固定测试密钥模拟两个客户端的写入、下载、冲突和删除。不读取后端 `.dev.vars`，不连接远端 D1。需要允许本机端口监听。

JSBox 原生界面和 `$http` NSData 请求传输仍需在 iOS 上验收；Node SQLite 和 workerd 测试不替代设备运行验证。

## 额度错误

更新 Worker 和客户端后，同步页及日志会区分 D1 每日读取额度、每日写入额度、账户存储额度和单库容量上限。每日读写额度提示北京时间 08:00（UTC 00:00）重置；存储不足不会提示等待次日恢复。额度错误立即停止自动重试，保留未确认请求和已提交游标，额度恢复后原样继续。

后端仅依据 Cloudflare 明确的超额错误分类；未知数据库故障仍提示暂不可用，不能把旧 Worker 返回的 `DATABASE_UNAVAILABLE` 推断成额度用尽。下载流即使已返回 HTTP 200，客户端也先检查顶层 `error`，拒绝不完整数据和游标。
