# 数据库同步

入口：**更多 → 数据库同步**。使用重新实现的 cloudflare-d1-sync JSON 协议（`/v1/write`、`/v1/sync`、`/v1/full-download`、`/v1/read`、`/v1/table-download`），不兼容旧版业务表后端。

## 使用

1. 通过三步引导了解部署、填写设备名、Worker HTTPS 根地址与 64 位小写十六进制主密钥，然后验证连接。
2. 选择同步内容。依赖图库的表必须同时选择图库记录。标签列表、搜索词随主记录打包，不单独选择。
3. 应用运行期间，每 30 秒尝试自动同步，也可点击“立即同步”。`$device.networkType === 0`、未配置连接、未选择内容、引擎忙碌或正在处理管理操作时跳过本轮，不排队堆积任务。
4. 如有冲突，进入按表汇总的冲突页，副标题显示各表冲突数。可批量保留全部本机或云端内容，也可进入某张表批量处理该表或逐条选择。表内记录仅查询本地冲突队列，首批加载 50 条，使用 JSBox `didReachBottom` 触底追加；浏览、刷新和翻页均不等待网络或引擎锁，右上角刷新从首批重新开始。单条详情先打开并显示本机内容，云端区域显示“正在读取云端内容”；引擎可用后通过 `/v1/read` 读取云端内容、更新时间与修改设备并刷新页面。读取期间可以返回或查看本机完整内容；失败在原位置显示原因并提供重试，不弹出阻塞式错误提示。云端数据就绪后才启用版本选择，确认时继续校验本机修订与云端版本。页面关闭后忽略迟到响应。保留云端会立即应用，使用本机则留待下次同步上传。
5. “暂停同步”只暂停后续定时任务，按钮变为“恢复同步”；不会中断当前任务，也不影响手动同步。暂停状态只保存在本次运行的内存中，重启应用后恢复默认自动同步。手动与自动任务共用引擎的并发锁；自动同步期间，主页同样显示“同步中…”。网络结果不确定时保留原始请求，下轮同步原样重放。
6. 数据与连接中可修改同步内容、连接设置、重新下载某项或全部内容，或脱离云同步。脱离会移除连接和同步状态、重置业务行同步版本，但保留业务数据、其他凭据及云端数据；有未确认上传时须先完成确认。

首次选择某张表时，本机已有数据保留为待上传意图。云端相同内容自动消除重复；不同内容保留为冲突。关闭表不会删除本地或云端记录，再次启用会按表下载及补拉。已有完整基线时，新增选择及单项重新下载使用 `/v1/table-download`，只分页读取目标表；之后从 start_seq 补拉变化，在当前页中过滤该表，追平后事务性替换该表镜像。单表流程不会推进正式 seq 或确认设备位置；其他已选内容仍由正常全局增量同步处理。首次建立基线、完整重下载或全局日志过期仍走完整恢复。关闭某项不会触发其他表重新下载。

API 地址和主密钥保存在 `assets/credentials.json` 的 `sync: {url, masterKey}`，沿用文件原子替换及 SQLite revision 恢复机制。安装包排除凭据文件和运行时数据库。Cookie、GitHub Token、WebDAV 凭据、AI 敏感参数、下载任务不上传。AI `selected` 和 WebDAV `enabled` 不进入 content；下载新增服务默认关闭，已有服务保留本机选择，删除服务会关闭本机选择。

v1-to-v2 迁移将 `config.githubToken` 保存到凭据文件的 `githubToken`，将 AI 表单中 `secure: true` 字段的值按服务 ID 保存到 `aiTranslation: { [id]: { [key]: value } }`，并清空数据库中的敏感默认值。后续修改 secure 标记时，值在数据库和凭据文件间转移；删除字段或服务会清理对应凭据。所有凭据修改使用同一套文件原子替换与 SQLite revision 恢复机制，不使用 `$keychain`。

同步日志显示无法应用的记录及失败类别，不保存主密钥、请求正文或底层数据库错误。管理页保留最近 50 条操作摘要，可按成功、提示、错误筛选；另显示最近 50 条记录应用错误。设备管理支持本机改名、禁用/重新启用其他设备，以及重新启用被禁用的本机。同步身份重建仅用于无未确认请求时的旧备份恢复；数据库及设备身份不能直接复制给另一个安装实例使用。

## 持久化状态

- `sync_enabled`：所选逻辑表。
- `sync_mirror`：已确认的云端 JSON、版本及 tombstone，无业务外键。
- `sync_pending`：本地待上传键、首次编辑的 base version、修订号及冲突状态。
- `sync_meta`：设备请求身份、已提交 seq、最近请求编号、原始未确认请求正文及对应修订号、完整下载和待单表下载标记、设备名、暂停状态与最近操作摘要。
- `sync_stage`：本轮分页下载的暂存记录。
- `sync_log`：按表/ID 保存最近一次无法应用的原因。
- `sync_control`：本地修订号及远端应用期间的写入跟踪开关。

初始化在业务库迁移完成之后、业务操作之前进行。触发器在业务写入同一事务内记录待上传意图，附属表变化也标记主记录；远端应用不会反向产生本地上传。其他设备的标签计数不会进入本机上传队列。

同一个运行实例的同步任务串行。上传前将最多十个不同键的有序请求序列化一次并落盘，传输 NSData UTF-8 字节；未确认结果前不能发送下一编号或切换服务器。已提交但响应丢失的请求原样重放。成功后按保存的修订号清理待上传项；发送期间的新修改继续保留，并更新其 base version。失败项保留冲突，不自动 forced。冲突确认绑定已展示的本机修订和内容，确认期间本机有修改会要求刷新。保留云端时严格校验并应用，失败会回滚并保留冲突；`found:false` 与带版本的 tombstone 分开处理。使用本机时以用户看过的云端版本为新基线，后续云端再变更会再次产生冲突，不无条件覆盖。点查不会推进全局游标，也不会把比镜像旧的响应当成新状态。

分页先暂存，按 sync_version 拒绝版本倒退。所有增量暂存请求使用 `include_self:true`，避免提前确认尚未提交的分页进度；业务应用与 seq 提交完成后才发送普通同步确认。完整下载从 start_seq 补拉至末页，随后切换镜像。中断后保留正式游标，下次清空暂存区重读；日志过期最多自动重启三次完整下载。

业务应用先图库记录，后外键关联表；正常页使用批量 SQL（每条 SQL 最多 900 个绑定参数），坏页回滚后再逐条用 SAVEPOINT 隔离。外键或内容约束失败只跳过本次业务写入，保留云端镜像和错误，后续同步再次尝试。磁盘、事务等基础设施错误回滚整轮应用和游标。通常尚未下载过的 tombstone 无需构造空的业务行；本地标签标记例外：由 namespace:name 恢复删除行，以继续隐藏网站下载的标签。云端从未存在过的标签删除意图会通过两个独立、可重试的 create/delete 请求建立 tombstone，期间保留本地删除意图；全局设置删除恢复本机默认值，删除版本保存在镜像中。

## 大数据量处理

上传队列使用 `(tablename, revision, id)` 条件索引，每次读取最多十条；上传确认只更新对应业务行的版本，不重放镜像或重载业务缓存。批次之间交还事件循环，过滤大量相同内容时也会让出执行时间。

下载只应用本轮暂存键和待重试错误记录，并跳过业务表中已有的相同版本。成功提交后只刷新受影响的缓存；搜索历史和书签的附属搜索词各用一次 JOIN 查询加载，避免逐条读取。完整下载仍保留整轮应用与游标一起提交的原子性。

同步页的进度文字最多每 500ms 更新一次，不在每批上传后重新读取凭据、统计整张队列或重建列表；完成后再刷新数量。没有服务端待下载总数接口，状态卡显示实际本轮下载记录次数（包括补拉时再次取得的记录），不估算待下载数量。

规模回归使用 15000 条搜索历史和 45000 条附属搜索词，覆盖完整上传、完整下载和重复空同步，并检查读取记录数量及写入调用数量随数据量线性增长。测试的本机耗时不代表移动设备或真实网络耗时。

## 额度错误

更新 Worker 和客户端后，同步页及日志会区分 D1 每日读取额度、每日写入额度、账户存储额度和单库容量上限。每日读写额度提示北京时间 08:00（UTC 00:00）重置；存储不足不会提示等待次日恢复。额度错误立即停止当前请求内的自动重试，保留未确认请求和已提交游标，额度恢复后原样继续。定时调度仍每 30 秒尝试；可通过“暂停同步”暂停后续尝试。

后端仅依据 Cloudflare 明确的超额错误分类；未知数据库故障仍提示暂不可用，不能把旧 Worker 返回的 `DATABASE_UNAVAILABLE` 推断成额度用尽。下载流即使已返回 HTTP 200，客户端也先检查顶层 `error`，拒绝不完整数据和游标。

## 请求诊断日志

同步网络请求使用 `appLog` 的 `info` 等级记录，包含请求编号、重试次数、方法、完整 URL、超时、请求头及 JSON 请求体。`Authorization`、`master_key` 等凭据字段会整体替换成 `[REDACTED]`，已配置的主密钥在任意文本中出现时也会被替换。日志使用独立副本，不改动实际请求头、正文或未确认请求的重放字节。

HTTP／网络错误、流式响应错误和写入冲突使用 `error` 等级，记录对应请求编号、接口、HTTP 状态、错误详情；非标准响应先脱敏，再截取最多 4000 字符。同步流程及管理操作失败也记录 `error`，取消和暂停不作为错误。日志沿用 `appLog` 的全局等级设置；开启调试模式时，请求与错误同时输出到控制台并保存到 `debug.db`。

`NOT_FOUND` 表示云端没有匹配的接口，错误提示会附带请求方法和路径。若失败路径为 `/v1/read` 或 `/v1/table-download`，需要检查配置的 Worker 地址和远端已部署版本是否包含新接口；仅凭错误码无法确定具体失败路径。HTTP 404 即使返回非 JSON 或同时附带传输错误，也按 HTTP 404 报告，不误报为 JSON 不完整，并且不重试明确的 4xx（429 除外）。

## 定时调度

`SyncScheduler` 在应用初始化全局定时器后注册唯一任务，首次在 30 个计时周期后执行，后续每 30 秒检查一次。定时器的同步回调调用内部异步流程并捕获所有失败；每轮完成后仍由引擎释放锁。管理页面等待输入、确认或执行操作时暂缓自动任务，避免与连接修改、内容选择等动作交错。恢复定时同步后在下一次检查时尝试，不立即追加任务。

调度启动、暂停、恢复、跳过原因、自动同步开始及完成通过 `syncLog` → `appLog` 记录为 `info`，失败记录为 `error`，沿用脱敏和全局日志等级。自动失败不弹出对话框；引擎错误仍保存到同步错误日志。自动成功更新最后同步时间，其详细结果在 appLog 中记录。定时调度依赖应用脚本运行，没有新增关闭应用后的系统唤醒任务。

## 批量处理冲突

全局与单表批量操作均先确认范围和数量，再按每批 50 条读取云端当前版本。全程占用引擎锁，定时和手动同步不能插入。全部处理按业务依赖顺序先处理图库记录，再处理关联表；仅操作已启用同步内容中的冲突。操作开始时固定本机修订边界，期间新增或改动的内容不会被无条件覆盖。

逐条沿用版本检查及原子应用：失败项回滚并保留冲突，其余项继续处理；网络或读取错误中断后，已成功处理的记录保留结果，尚未处理的冲突保留。批量保留本机不立即上传，以读取到的云端版本为新基线；云端后续变化仍可能产生冲突。批量保留云端会应用删除或不存在状态。开始、完成及逐条错误通过 appLog 记录，页面显示已处理、失败和剩余数量。
